# TmlUs CLI 设计语言

## 1. 设计定位

TmlUs 的 CLI 视觉语言应呈现“卡哇伊二次元终端工作台”的气质：它不是冷冰冰的系统工具，也不是过度娱乐化的玩具，而是一个带有 TML 团队个性、能够陪伴开发者启动 AI 工作流的命令行界面。

核心关键词：

- **Kawaii Terminal**：可爱、轻盈、有启动仪式感，但保持开发工具的清晰度。
- **Anime Atelier**：像一个二次元风格的 AI 开发工坊，有光感、星光、缎带和魔法启动氛围。
- **Spec-Driven Workspace**：所有视觉表现都服务于规范化开发，不牺牲可读性、可复制性和自动化安全。

## 2. 设计原则

### 2.1 先可读，再可爱

CLI 首先是工作界面。所有装饰、颜色和动效都不能妨碍用户读取命令状态、错误信息和下一步操作。

要求：

- 重要信息必须有稳定文本，不只依赖颜色表达。
- 颜色用于分层和强调，不用于承载唯一语义。
- 输出在无色终端、窄终端、CI、管道输出中必须可降级。

### 2.2 有启动仪式，但不拖慢开发

TmlUs 可以有短暂的启动动效，让工具更有记忆点，但动效必须短、轻、可跳过。

要求：

- 启动动效默认控制在 1 秒以内。
- `--no-banner`、`--quiet`、`TMLUS_NO_BANNER=1` 必须关闭装饰性输出。
- `version`、CI、非 TTY 输出必须保持干净。

### 2.3 终端原生，不依赖图片

CLI 视觉必须使用终端原生能力构建，包括 ANSI 颜色、Unicode 线框、ASCII 字标、文本进度条和轻量字符动效。

要求：

- 不依赖浏览器、图片、外部渲染服务或 bitmap 资源。
- 所有关键视觉都要有 ASCII/monochrome fallback。
- 终端宽度不足时使用 compact 版本。

## 3. 视觉基因

### 3.1 标志性构图

TmlUs 的高识别度 CLI 界面采用“终端卡片”构图：

```text
╭──────────────────────────────────────────────────────────────────────────────╮
│ ● ● ●  tmlus.exe --wake-up                                                   │
├──────────────────────────────────────────────────────────────────────────────┤
│ ✦                      ◇                     ✧                      +        │
│                                                                              │
│                            ◆ TML AI DEV ATELIER ◆                            │
│                   .-~~~~~~~ magical startup halo ~~~~~~~-.                   │
│                          ████████╗ ███╗   ███╗ ██╗                           │
│                          ╚══██╔══╝ ████╗ ████║ ██║                           │
│                             ██║    ██╔████╔██║ ██║                           │
│                             ██║    ██║╚██╔╝██║ ██║                           │
│                           ...                                                │
│                                                                              │
│ tmlus > 正在召唤 TML AI 开发工作台...█                                        │
│ ◇ profile: kawaii-spec-driven / skills, commands, specs are twinkling        │
│ ✦ status: TML workspace is warming up                                        │
│                         [██████████████████████████]                         │
╰──────────────────────────────────────────────────────────────────────────────╯
```

该构图由 6 个层次组成：

| 层次 | 元素 | 作用 |
|:---|:---|:---|
| Chrome | 三色窗口点 + `tmlus.exe --wake-up` | 建立“终端窗口”语义 |
| Sparkle | `✦`、`◇`、`✧`、`+` | 形成卡哇伊、魔法启动氛围 |
| Ribbon | `◆ TML AI DEV ATELIER ◆` | 建立品牌标题 |
| Halo | `.-~~~~ magical startup halo ~~~-.` | 提供二次元启动仪式感 |
| Lettermark | TML ASCII/Unicode 字标 | 形成第一视觉记忆点 |
| Console Lines | prompt、profile、status、progress | 回到工具状态与可读信息 |

### 3.2 字标风格

TML 字标应使用粗体块状字符，表达“工具感”和“标志感”。首选 Unicode block art，降级时使用纯 ASCII。

首选字标：

```text
████████╗ ███╗   ███╗ ██╗
╚══██╔══╝ ████╗ ████║ ██║
   ██║    ██╔████╔██║ ██║
   ██║    ██║╚██╔╝██║ ██║
   ██║    ██║ ╚═╝ ██║ ███████╗
   ╚═╝    ╚═╝     ╚═╝ ╚══════╝
```

降级字标：

```text
TTTTTTT  M     M  L
   T     MM   MM  L
   T     M M M M  L
   T     M  M  M  L
   T     M     M  LLLLLLL
```

## 4. 色彩系统

TmlUs CLI 使用糖果霓虹色，但必须控制密度，避免全屏高饱和导致疲劳。

| Token | RGB | HEX | 用途 |
|:---|:---|:---|:---|
| `pink` | `255, 143, 216` | `#ff8fd8` | 主品牌强调、光标、星光、关键状态 |
| `aqua` | `136, 247, 255` | `#88f7ff` | 技术感、profile、进度条主色 |
| `mint` | `170, 255, 216` | `#aaffd8` | prompt、成功感、窗口点 |
| `gold` | `255, 230, 129` | `#ffe681` | 仪式感、提示符、辅助星光 |
| `violet` | `197, 161, 255` | `#c5a1ff` | 边框、阴影感、进度条底色 |
| `white` | `255, 248, 255` | `#fff8ff` | 主文本 |
| `panel` | `36, 21, 54` | `#241536` | 深色终端卡片背景参考 |

使用规则：

- 边框优先使用 `violet`，避免高亮色抢占内容。
- prompt 使用 `mint`，状态关键词使用 `pink` 或 `aqua`。
- 进度条使用 `aqua` 填充、`violet` 弱化空槽。
- 大面积文本使用 `white` 或默认终端色，避免全彩污染。
- 无色环境必须去除 ANSI 控制码，保留文本结构。

## 5. 信息层级

### 5.1 CLI 页面结构

通用 CLI 输出应遵循以下层级：

```text
品牌/上下文
当前动作
关键状态
用户可执行的下一步
详细日志或诊断信息
```

对应样式：

| 信息类型 | 建议样式 |
|:---|:---|
| 品牌启动 | 终端卡片 + TML 字标 |
| 当前命令 | `tmlus > ...` prompt 行 |
| 成功状态 | `mint` 或 `aqua` + 简短句子 |
| 警告状态 | `gold` + 明确说明 |
| 错误状态 | 使用红/粉强调，但必须有清晰文本 |
| 诊断详情 | 弱化色或普通文本，按列表分组 |
| 下一步操作 | 明确命令，使用 monospace 文本 |

### 5.2 语气规范

TmlUs 的 CLI 文案应保持轻快但不幼稚。

推荐：

- `正在召唤 TML AI 开发工作台...`
- `TML workspace is warming up`
- `skills, commands, specs are ready`
- `profile: kawaii-spec-driven`

避免：

- 过多颜文字、网络热词或影响专业感的玩笑。
- 错误信息过度卖萌，导致问题不清楚。
- 长句堆叠，影响终端扫读。

## 6. 组件规范

### 6.1 终端卡片

终端卡片用于高识别度场景，例如启动、初始化完成、重要阶段切换。

规则：

- 宽屏完整卡片建议宽度约 78 字符内容区。
- 小于完整宽度时切换 compact 样式。
- CI、非 TTY、日志输出中不要使用装饰卡片。
- 卡片内信息不要超过一屏，避免用户必须滚动才能看到命令结果。

### 6.2 Ribbon

Ribbon 用于表达当前模式或品牌标题。

格式：

```text
◆ TML AI DEV ATELIER ◆
```

规则：

- 只用于启动、欢迎、重大完成状态。
- 不用于普通日志行。
- 可使用渐变色，但必须在无色环境中保持可读。

### 6.3 Sparkle

Sparkle 用于制造轻量卡哇伊氛围。

允许字符：

```text
✦ ◇ ✧ +
```

规则：

- 每个卡片最多 4 个主要 sparkle。
- 不要在错误信息中使用 sparkle。
- 非 TTY 或 monochrome 模式可以删除或替换为 `*`、`+`。

### 6.4 进度条

进度条用于启动、安装、同步、诊断等阶段。

推荐格式：

```text
[████████████░░░░░░░░]
```

规则：

- 进度条必须配合状态文本，不单独出现。
- 长任务应显示阶段名，短启动动效可以只显示装饰性进度。
- 不确定进度可使用 spinner 或流动条，不要伪造百分比。

### 6.5 Prompt 行

Prompt 行是把装饰拉回工具语境的关键。

推荐格式：

```text
tmlus > 正在召唤 TML AI 开发工作台...█
```

规则：

- `tmlus` 使用 `mint`。
- `>` 使用弱化色。
- 当前动作使用主文本色。
- 动态光标只在 TTY 动效中出现。

## 7. 动效规范

动效只服务于“启动感”和“状态变化”，不能制造认知负担。

### 7.1 启动动效

推荐帧数：4-6 帧。  
推荐帧间隔：80-120ms。  
推荐总时长：不超过 1 秒。

动效可以包含：

- TML 字标逐行显现。
- Ribbon 颜色轻微流动。
- Halo 长度轻微变化。
- Sparkle 位置或颜色轮换。
- 进度条短暂填充。

动效不应包含：

- 大范围清屏影响用户已有上下文。
- 无限循环。
- 闪烁过快的高亮色。
- 影响命令执行的等待。

### 7.2 降级策略

| 场景 | 行为 |
|:---|:---|
| TTY + 宽屏 + 支持颜色 | animated |
| TTY + 宽屏 + `TMLUS_BANNER_STATIC=1` | static-full |
| TTY + 窄屏 | static-compact |
| TTY + 无色 | monochrome |
| CI | suppressed |
| stdout 非 TTY | suppressed |
| `version` | suppressed |
| `--quiet` / `--no-banner` / `TMLUS_NO_BANNER=1` | suppressed |

## 8. 适用场景

### 8.1 适合使用完整视觉语言

- `tmlus` 默认启动
- `tmlus init` 进入交互式初始化
- 初始化完成总结
- 首次安装后的欢迎界面
- 重要 profile 切换

### 8.2 适合使用轻量样式

- `tmlus doctor`
- `tmlus sync`
- `tmlus skill list`
- `tmlus command list`
- 中间过程日志

轻量样式可以只保留：

```text
✦ TmlUs
◇ profile: xxx
```

### 8.3 禁止使用装饰样式

- `version`
- JSON / machine-readable 输出
- CI logs
- 重定向或管道输出
- 明确 quiet/no-banner 的调用

## 9. 后续扩展方向

后续新增 CLI 页面时，应优先复用此设计语言，而不是为每个命令单独设计风格。

可扩展方向：

- `init` 使用“启动仪式 + 步骤进度”的完整卡片。
- `doctor` 使用“诊断面板 + 分组状态”的轻量卡片。
- `skill` 使用“资源商店/工坊”语义，但保持终端原生。
- `sync` 使用“契约同步/能量流动”语义，配合短进度条。
- `error` 使用清晰问题定位，不做可爱化装饰。

## 10. 验收清单

任何新的 CLI 视觉设计都应满足以下检查项：

- [ ] 在 82 列以上终端中布局不换行。
- [ ] 在 42-81 列终端中有 compact fallback。
- [ ] 在无色终端中没有 ANSI 残留。
- [ ] 在 CI 和非 TTY 环境中不输出装饰动效。
- [ ] `--quiet`、`--no-banner` 可关闭装饰输出。
- [ ] 关键信息不依赖颜色才能理解。
- [ ] 动效不超过 1 秒，且不阻塞命令功能。
- [ ] 风格符合 `kawaii-terminal-v1`：可爱、明亮、有启动仪式，但仍是专业开发工具。
